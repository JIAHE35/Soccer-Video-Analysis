# V0.6: Restricted Pitch Mapping

## Objective

Show how existing detections can be converted from image coordinates to a
local 2D pitch view. Unlike a full-match calibration system, this experiment
only supports one manually selected continuous shot and one local valid region.
The V0.5 detector, ball tracker, thresholds, and previous outputs are unchanged.

These times refer to the file timeline, not the broadcast match clock. The clip
is extracted by frame number, and the matching full-source CSV rows are selected
using an offset of 2241 frames. No new YOLO inference is performed, keeping the
detection baseline unchanged while testing coordinate mapping.

```bash
ffmpeg -n -i data/soccervideo_cfr.mp4 \
  -vf "trim=start_frame=2241:end_frame=2598,setpts=PTS-STARTPTS" \
  -an -c:v libx264 -pix_fmt yuv420p -movflags +faststart \
  data/v06_homography_clip.mp4
python src/map_pitch.py
python src/calibrate.py --review
```

The `-n` flag and default mapping behavior protect existing files. To regenerate
mapping files deliberately, use `--overwrite`; otherwise choose a new output
name. Videos and datasets remain local and ignored by Git.

## Implementation

| File | Responsibility |
| --- | --- |
| `src/homography.py` | Named landmarks, homography fitting, keyframe interpolation, ROI validation |
| `src/pitch.py` | Pitch diagram, role markers, projected calibration-line overlays |
| `src/map_pitch.py` | CSV frame alignment, video rendering, coordinates and provenance export |
| `src/calibrate.py` | Interactive landmark editing and noninteractive review sheet |
| `config/v06_pitch_calibration.json` | Clip metadata, manual points, and valid-region polygon |
| `tests/test_homography.py` | Geometry, interpolation, CSV semantics, and real synthetic-video integration |

The image-to-pitch homography is fitted with OpenCV from at least four named,
non-collinear ground-plane points. See the official
[OpenCV homography tutorial](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html).
References include penalty-area corners, six-yard-area corners, the arc/box
intersections, the penalty spot, the far pitch corner, and goalpost bases.
Goalpost tops must not be used: they are not on the ground plane.

The configuration contains 13 keyframes at local frames 0, 30, 60, 90, 120, 150,
180, 210, 240, 270, 300, 330, and 356. Occluded far six-yard corners at frames
90, 270, 300, and 330 were omitted rather than guessed. More than four visible
reference points remain at every keyframe.

For intermediate frames, the four virtual ROI corners are projected into both
neighboring images, their image positions are linearly interpolated, and a new
homography is fitted. Homography coefficients are not interpolated directly.
This compensates approximately for smooth camera panning/zooming; it is not
automatic line tracking or a general camera-motion model.

Coordinate convention: right goal at x=105 m, far touchline at y=0 m. The valid
region is the right penalty area: 88.5 <= x <= 105 and 13.84 <= y <= 54.16.
The full diagram gives context, but objects are only drawn within this local
region. No extrapolation is allowed beyond the calibrated frame range.

- People, including goalkeepers, referees, and unknown roles: bbox bottom-center.
- Detected football: bbox center, explicitly a ground-plane assumption.
- Predicted football: same projection, with the V0.5 `predicted` state retained.
- Outside-region objects: retain source bbox and ID, but leave pitch x/y empty.

## Outputs And Initial Observation

| File | Contents |
| --- | --- |
| `outputs/v06_pitch_mapping.mp4` | 1800 x 588 H.264 MP4, 30 FPS, left video / right map |
| `outputs/v06_pitch_mapping.csv` | 4,281 detection rows plus mapping metadata |
| `outputs/v06_pitch_mapping.json` | Input SHA-256 hashes, counts, keyframe fit residuals |
| `outputs/v06_calibration_review.jpg` | 13 keyframes and 12 midpoint line-overlay checks |

The initial local run maps 2,904 rows. The remaining 1,377 rows are outside the
restricted region, not counted as missed detections. There are 146 observed-ball
rows and 78 predicted-ball rows in the selected interval; these counts include
both mapped and unmapped balls and are not accuracy scores.

Each CSV row includes local `frame`/`time`, `source_frame`/`source_time`, original
ID/role/bbox/confidence/ball state, anchor x/y, pitch x/y, `homography_valid`,
`mapping_reason`, `position_basis`, and `shot_id`. Predicted balls have neither a
track ID nor a fabricated detection confidence. Retaining the source frame
allows every row to be checked against the original video.

Manual keyframe fit RMSE ranges from about 1.63 to 7.41 image pixels. The fit is
rejected above 12 pixels. These are residuals on the fitted landmarks, NOT an
independent measurement of pitch-coordinate accuracy. Review overlays at all
keyframes and midpoints were visually inspected; representative output frames
were checked at the beginning, middle, and end.

The generated video was fully decoded and verified to contain 357 frames at
30 FPS, with a duration of 11.9 seconds. The test suite contains 60 passing tests
at this milestone, including a synthetic-video integration test.

## Editing Calibration

```bash
python src/calibrate.py --frame 0 --landmarks \
  penalty_far penalty_near six_yard_far six_yard_near penalty_spot corner_far
```

Click the named landmarks in the printed order. Right-click undoes a point;
`S` validates and saves the complete keyframe; Escape cancels without saving.
Choose only points visible on that frame. At least four unique non-collinear
landmarks are required. Adding a frame between existing keyframes can reduce
interpolation drift. After editing, rerun `--review`, then regenerate mapping.

If detections are regenerated directly on this clip instead of the original
video, pass `--detections PATH --detections-frame-offset 0`. Detection CSV rows
must still follow the V0.5 schema and the clip's 30 FPS timeline.

## Limitations And Next Step

1. The 105 x 68 m pitch size is an assumption, not a surveyed stadium dimension.
2. Manual points and approximate interpolation can drift, especially with rapid
   camera movement; no scene-cut recovery or automatic recalibration exists.
3. Bounding-box bottoms approximate feet. Occlusion, cropped boxes, and poor
   detections can move a person's mapped position or reject a boundary object.
4. Airborne ball centers are not ground-plane points. Their mapped dots are
   illustrative projections, not true ball ground locations or 3D positions.
5. V0.5 role errors, duplicate detections, ID switches, and predicted-ball drift
   remain unchanged. A cleaner map does not fix upstream errors.
6. This clip cannot support whole-match coverage, true player running distances,
   or reliable ball speed statistics. The map does not certify metric accuracy.

Before V0.7 quantitative statistics, validate additional held-out line points,
inspect ID continuity, and label periods where geometry is trustworthy.
Any first heatmap should cover only this valid local region and explicitly
exclude unvalidated frames and predicted/airborne ball estimates.
