# V0.3 - Player Tracking with ByteTrack

**Status:** Complete

**Git reference:** `7e6d346`

**Milestone:** Assign temporary IDs to detected people while keeping ball
detection independent.

## Goal

V0.3 changed the output from isolated per-frame player detections into short
temporal tracks:

```text
person detections -> ByteTrack -> player #ID
ball detections   -> independent YOLO pass -> ball without ID
```

The IDs are tracker associations, not player names or shirt numbers.

## Changes from V0.2

- Replaced person-only `predict()` calls with Ultralytics `track()` and
  ByteTrack.
- Enabled persistent tracker state across streamed frames.
- Allowed ByteTrack to see person detections down to `0.1` while displaying
  only people at or above the `0.5` player threshold.
- Added `player #ID` labels when a track ID is available.
- Kept the ball outside ByteTrack and ran a separate ball detection pass.
- Lowered ball confidence from `0.3` to `0.18` to retain more small candidates.
- Added `lap>=0.5.12`, which the tracking pipeline requires.
- Preserved the V0.2 grass-field filtering before drawing annotations.

## What improved

- Visible people can keep the same ID across adjacent frames.
- Player tracks provide the foundation for future trajectories and statistics.
- Ball sensitivity can be changed without affecting ByteTrack's person input.
- Balls never receive misleading person-style IDs.
- Tests cover tracked and untracked people, ball labels, separate model passes,
  empty frames, output FPS, and output frame count.

## Observed results

- Many visible people retain IDs between 20.0 and 20.5 seconds, although some
  IDs switch.
- At 46 seconds, the lower ball threshold accepts a penalty-spot false positive
  with confidence `0.26` that V0.2 suppresses.
- At 80 seconds, the visible ball is still missed.

These are local spot checks, not measurements against labeled ground truth.

## Limitations discovered

- Occlusion, rapid camera movement, cuts, and replays can cause ID switches or
  new IDs.
- IDs do not persist reliably across separate shots.
- Every tracked person is still called `player`; teams and referees are not
  separated.
- Ball detection remains intermittent and contains false positives because the
  general-purpose model sees very few pixels for a distant ball.
- Two model passes per frame make V0.3 slower than V0.2.

These limitations motivate V0.4's team and role classification. Ball tracking
will remain a separate later milestone.

## Run this version

```bash
python src/detect.py \
  --source data/soccervideo_cfr.mp4 \
  --output outputs/v03_player_tracking.mp4 \
  --player-conf 0.5 \
  --ball-conf 0.18 \
  --min-field-green-ratio 0.25
```

The retained `outputs/comparison_v02_v03.mp4` artifact shows V0.2 and V0.3 at
matching timestamps. It is a version comparison, not a controlled tracking
benchmark, because the ball threshold also changed.
