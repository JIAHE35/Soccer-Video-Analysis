# V0.7: Local Trajectories And Observed-Position Heatmaps

## Objective And Scope

Turn the existing V0.6 coordinates into a small, reproducible local analysis:
short contiguous trajectories, two-team position distributions, and data-quality
statistics. Use exactly the same 74.7-to-86.6-second source interval: 357 frames,
30 FPS, 1280 x 588. Do not rerun YOLO, retrain models, change V0.5 thresholds,
or replace the V0.6 calibration. This is not a whole-match analytics system.

## Inputs And Execution

| Input | Purpose |
| --- | --- |
| `data/v06_homography_clip.mp4` | Original selected clip for the left video panel |
| `outputs/v06_pitch_mapping.csv` | Existing bboxes, IDs, roles, mapped positions, and ball states |
| `outputs/v06_pitch_mapping.json` | V0.6 input hashes and frame metadata |

```bash
python src/analytics.py
```

FFmpeg is required, but there are no new Python dependencies. Defaults resolve
from the repository root. The CSV follows the V0.6 schema. The loader validates
frame range, timestamps, source-frame offset, shot ID, roles, box geometry,
confidence, mapped-coordinate bounds, and ball semantics. The clip and
calibration hashes must match the V0.6 report. Edited calibration requires
regenerating V0.6 mapping first.

The exported V0.7 report hashes the actual mapping CSV and report, preserving
which inputs were analyzed. V0.6 did not hash its output CSV, so this provenance
does not prove that CSV positions are unedited or independently accurate.

## Trajectories

People use the existing bbox-foot projection. Each temporary ID owns separate
contiguous fragments; no cross-ID merging or identity recovery is attempted.
A fragment breaks when a frame is missing, the mapping is invalid, the same
ID occurs more than once in a frame, the assigned role changes, or a nominal
position jump exceeds the configured threshold. When a person is absent or
invalid, its old trail disappears rather than suggesting continued observation.

Only the current fragment's last two seconds are shown. Every point retains its
frame number, and summary fragments retain start/end frames, sample counts,
observed duration, role, and starting reason. A single-sample fragment has one
frame of observed duration but no motion line. This is observation time, not
the elapsed time between its first and last samples.

Balls remain ID-free. Detected and predicted states are retained, with a solid
line for observed-to-observed samples and a thinner dashed line for segments
touching predictions. Missing or unmapped ball frames break the trail. All ball
positions are ground-plane projections, including airborne observations; there
is no automatic airborne detector and no claim of true 3D or ground location.

## Heatmap Definition

Each accepted team-person observation adds `1 / FPS` seconds to a nominal
1 m x 1 m pitch-coordinate cell. Team A and Team B use the same linear color
scale. Assigned goalkeepers are included in their team. Untracked team people
can contribute to position distributions but never receive inferred trajectories.
Referees, unknown roles, balls, invalid mappings, and repeated same-frame IDs
do not contribute to heatmaps.

Only the right penalty-area ROI is displayed. No Gaussian smoothing spreads
samples across the boundary. A bin intersecting the ROI boundary is drawn only
inside the polygon. Exact edge coordinates are retained in the boundary bin.
Blank areas outside the ROI are unobserved by this experiment, not evidence of
zero player activity. Blank cells within the ROI have no accepted samples.

Two different time statistics are deliberately separate:

- `person_observation_seconds`: all accepted team-person samples divided by FPS.
  Two people observed for one second contribute two person-seconds.
- `frames_with_member_seconds`: frames with at least one accepted member divided
  by FPS. This cannot exceed the analyzed duration.

Neither statistic measures possession, unique real-player time, or team dominance.

ground-truth recall or ball-coordinate accuracy. The JSON ball segments contain
only valid locally mapped ball samples, with states retained.

## Settings And Verification

```bash
python src/analytics.py --trail-seconds 2 \
  --max-person-step-m 1.5 --max-ball-step-m 5 \
  --output-dir outputs/v07_alternative
python -m unittest discover -s tests
```

Default jump limits are 1.5 nominal meters for people and 5 for balls **per
frame**. They are display guards, not validated speed constraints; tune them
alongside FPS and calibration quality. No distances or speeds are exported.

Existing V0.7 files are protected. `--overwrite` explicitly replaces only this
version's three outputs; upstream videos and CSVs remain unchanged. Files are
generated in a temporary directory and published only after successful encoding.
Default publication uses atomic no-clobber links, protecting even files created
by another process during generation. Non-file targets and output symlinks are
rejected. Explicit replacements retain recovery copies until publication
finishes; a write failure restores the files replaced by this invocation.
If restoration itself fails, recovery files are preserved and an error names
them. This is rollback protection, not a power-loss-proof multi-file transaction.
The clip is processed frame-by-frame, including frames without detections.

The suite has 80 passing tests at this milestone. Seventeen initial tests were
written before implementation and initially failed because V0.7 was absent.
They cover gaps, invalid regions, ID/role changes, jumps, duplicate IDs,
untracked samples, goalkeepers, person-second units, predicted balls, boundary
cells, empty heatmaps, malformed timestamps, duplicate balls, input hashes,
overwrite protection, and a real synthetic-video pipeline. Three additional
regression tests reproduce concurrent output creation, a directory output target,
and failure halfway through publication, verifying no clobbering or partial
replacement of existing outputs.

## Limitations And Next Step

V0.7 does not fix upstream missed/duplicate detections, incorrect kit roles,
ID switches, or calibration drift. Different IDs can still represent the same
person, and an ID can silently switch between nearby people without triggering
the jump guard. Duplicate real-person detections with different IDs can still
inflate heatmap counts. The high fragment count makes these limitations visible
instead of hiding them by automatically stitching tracks together.

These are exploratory visualizations of manually reviewed local mapping data,
not independently ground-truth-validated analytics. The pitch dimensions are
assumed and airborne ball projections can be misleading. Do not infer true
running distance, speed, possession, or whole-match tactics from this clip.

Next, validate held-out ground-plane points and manually review selected ID
fragments. Longer continuous footage and stronger identity/calibration evidence
are needed before quantitative physical or tactical statistics.
