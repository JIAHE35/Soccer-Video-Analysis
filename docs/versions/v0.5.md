# V0.5 - Ball Tracking and Short-Gap Prediction

**Status:** Complete

**Git reference:** V0.5 implementation commit

**Milestone:** Replace independent per-frame ball boxes with one temporally
associated ball track and clearly marked short-gap predictions.

## Motivation

V0.4 draws every YOLO sports-ball candidate that passes the grass filter. A
real ball disappears immediately when YOLO misses one frame, while a pitch
marking can appear as another unrelated ball. V0.5 adds temporal context:

```text
YOLO ball candidates
  -> grass and box-shape filtering
  -> predicted-position association
  -> two-hit track confirmation
  -> constant-velocity short-gap prediction
  -> one ball result per frame
```

People still use ByteTrack and kit-color role classification. The ball remains
independent and never receives a person track ID.

## Implementation

- Added `src/ball_tracker.py` with `BallCandidate`, `BallTrackResult`, and
  `BallTracker`.
- Rejects invalid, flattened, unusually large, or visually implausible
  candidate boxes before association.
- Uses candidate texture and saturation to suppress smooth white pitch marks.
- Starts from the highest-confidence valid candidate and requires two nearby
  detections before displaying a confirmed track.
- Requires low-confidence tentative tracks to be near a player, move clearly,
  or accumulate high-confidence evidence before confirmation.
- Scores later candidates using distance from the predicted center with a
  smaller confidence contribution.
- Estimates image-space velocity from accepted detections.
- Produces at most eight predicted frames when detections temporarily vanish.
- Rejects distant candidates instead of allowing an abrupt track jump.
- Displays detected balls with a solid blue box and predictions with a dashed
  blue `ball predicted` box.
- Adds `ball_state` to CSV. Predicted rows leave YOLO confidence empty because
  no model detection exists on those frames.

## Default parameters

| Parameter | Default | Meaning |
| --- | ---: | --- |
| `--ball-conf` | `0.18` | Minimum YOLO confidence for a candidate |
| `--ball-confirm-hits` | `2` | Nearby detections needed to confirm a track |
| `--ball-max-missing` | `8` | Maximum consecutive predicted frames |
| `--ball-max-distance` | `120` | Base image-space association gate in pixels |
| `--ball-max-box-side` | `48` | Largest accepted candidate side in pixels |
| `--ball-max-aspect-ratio` | `1.8` | Widest accepted horizontal aspect ratio |
| `--ball-min-texture-std` | `25` | Minimum grayscale variation for a textured candidate |
| `--ball-min-saturation` | `180` | Alternative saturation evidence for a colored ball |

At 30 FPS, eight missing frames represent about 0.27 seconds. These defaults
are match-specific starting points, not universal football-tracking settings.

## Output

| Artifact | Purpose |
| --- | --- |
| `outputs/v05_ball_tracking.mp4` | V0.4 annotations plus detected/predicted ball track |
| `outputs/v05_detections.csv` | People, roles, ball boxes, confidence, and ball state |

The CSV schema is:

```text
frame,time,track_id,role,x1,y1,x2,y2,confidence,ball_state
```

For people, `ball_state` is empty. For a detected ball it is `detected`; for a
short-gap estimate it is `predicted` and `confidence` is empty.

## Verification

- Unit tests cover confirmation, player-proximity evidence, candidate
  association, short-gap prediction, expiration, jump rejection, box shape,
  visual appearance filtering, and explicit reset.
- The integration test verifies that video labels and CSV rows distinguish a
  measured ball from a predicted ball.
- Generated a full `1280x588`, 30 FPS, 3534-frame video with a duration of
  117.8 seconds.
- Exported 32,118 detection rows: 1,068 measured ball rows, 611 predicted ball
  rows, and 30,439 person rows.
- Every frame contains at most one ball row. The longest predicted run is eight
  frames, and all predicted rows leave YOLO confidence empty.
- At the previously documented 46-second failure case, the smooth penalty-spot
  candidate is suppressed. Around 80 seconds, a short detection gap is bridged
  with a visibly distinct `ball predicted` box.

## Known limitations

- Constant-velocity prediction cannot model abrupt kicks or camera motion.
- Image-space distance has different physical meaning at different zoom levels.
- Pitch markings with enough texture or color variation can still pass the
  appearance heuristic.
- Predictions bridge only short gaps and do not recover long occlusions.
- Shot-boundary detection and automatic state reset are not implemented yet.
- This version does not train a football-specific detector.

## Out of scope

- Homography and real-world pitch coordinates.
- Possession, pass, speed, and distance statistics.
- Identity recovery across cuts and replays.
- Custom football-detector training.
